#### 部署环境

##### 前言

当前敏感字段分级分类器,没有实现web服务,以python本地文件方式启动,也没有将相关的依赖打包,运行时候需要依赖环境和该环境的解释器, 因此需要部署依赖环境,启动时候指定具体环境下的解释器.

部署步骤

1. 部署python环境
	1. 徐州环境为win7,64位,部署python3.8,64位
	2. 将python3.8压缩包上传,解压安装并配置环境变量
2. 部署C++环境
	1. 部分依赖基于C++实现,需要相关的环境
	2. 上传VC_redist_X64.exe到电脑中,解压,安装
3. 部署db2依赖
	1. python3.8针对db2的连接驱动需要手动引入
	2. 上传ntx64_odbc_cli文件夹,在代码头部显示引入,ntx64_odbc_cli\clidriver\bin
4. 部署nltk依赖
	1. nltk切词器的依赖离线包,建议直接放置C盘根路径下,代码中默认支持从路径查找
5. 创建虚拟环境
	1. 在python开发中,通常建议创建虚拟环境,目的为隔离环境,防止不同项目间的依赖冲突
	2. 但是在该场景下,仅有一个项目,因此创建虚拟环境不强求,虚拟环境的本质就是创建多个文件夹,通过每个文件夹下的解释器执行该环境的资源,实行隔离
	3. 首先通过 python -m venv 虚拟环境名称, 执行后,将创建出一个环境名称同名的文件夹,这里采用的隔离方式为venv轻量隔离
	4. 进入该文件夹,到Scripts目录下 执行activate,这里将激活该环境并进入此环境中
6. 迁移依赖至内网
	1. 使用pip下载相关的依赖,支持联网和读取本地
	2. 首先在联网电脑中,使用 pip install XX 的方式下载依赖,然后可以通过 pip list , pip freeze的方式查看下载下的依赖项
	3. 通过 pip freeze > requirements.txt 将联网电脑中已有依赖列表下载到本地
	4. 通过 pip download -r requirements.txt -d packages 的方式将 本地依赖列表中的依赖以离线包的方式下载到 packages文件夹中
	5. 接着将 packages文件夹 和 requirements.txt 上传到内网电脑中,记住相应的位置
	6. 在内网中执行 pip install --no-index --find-links=packages -r requirements.txt,其中的 packages换成内网下的 packages文件夹绝对地址, requirements.txt 换成内网下的 requirements.txt绝对地址
	7. 部分依赖可能是压缩包的方式或者是由于依赖加载的顺序导致安装失败,执行 pip install  该依赖的绝对地址,依据报错详细修改
	8. 注意, 内网电脑为win7, 联网电脑可能不是win7,虽然都是pyhton3.8,但是不同的依赖版本支持不同的系统版本,所以会出现 联网电脑的版本过高,无法在内网安装的情况,此时寻找适合的版本号
7. 运行
	1. 目前通过cmd命令启动项目,
	2. 进入项目的存储路径
	3. 指定环境下的python解释器绝地路径 -m 项目名称.main 传参的方式的启动项目
