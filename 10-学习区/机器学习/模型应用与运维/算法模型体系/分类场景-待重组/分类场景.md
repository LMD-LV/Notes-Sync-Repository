### 模型底层


模型其实是通过**一个统一的损失函数**（通常是 Softmax+交叉熵）来同时学习所有类别的。交叉熵损失会对每个样本都计算一次, 
	**样本不平衡时**，如果一个类别在训练集中只有 1% 的样本，而另一个有 50%，模型在优化时会更“在意”那 50% 的类别——因为那部分样本贡献了绝大多数梯度。

**加权交叉熵**就简单地在每个样本的损失上乘一个权重, 支持自定义各分类的权重,或者按照出现次数的反比 的方式拉平各个分类的损失权重

### 训练样本


正例和负例是对**样本所属类别的逻辑定义**，是一种相对概念（取决于当前任务的 “目标类别”）
正例: 指属于当前任务 “目标类别” 的样本。
负例 : 指不属于当前任务 “目标类别” 的样本。

正样本和负样本是**正例和负例的具体数据实例**，是实际用于训练 / 测试的样本数据

对抗样本是一种**特殊的 “干扰样本”**，它是通过对原始样本进行微小、人眼难以察觉的修改后，导致模型误判的样本。其核心目的是 “欺骗模型”，暴露模型的脆弱性, 可检验模型是否能抵御微小干扰（例如 “pass_word” 是否被正确识别为密码），帮助提升模型稳定性。

伪标签对抗: 在训练集中添加能对抗噪声的样本,将噪声拉平

概率模型（如逻辑回归、神经网络）：通过 Softmax 函数将输出转化为概率分布，每个类别对应一个 0-1 之间的概率值，总和为 1。例如，样本属于 “姓名” 的概率为 0.6，“其它” 的概率为 0.3，则模型预测为 “姓名”。
非概率模型（如 SVM）：通过决策边界的距离衡量置信度，距离越远，置信度越高。



“分类是独立的”，这在**模型预测阶段**是对的（每个样本的预测只依赖其特征）。但在**训练阶段**，模型通过最小化整体损失来学习参数，而不平衡的样本分布会导致损失被多数类 “主导”。加权损失函数的作用是**重新平衡各类别的影响力**，使模型能平等地学习所有类别的特征模式, 类别不平衡的问题本质是**样本量差异导致模型对稀有类的学习不足**


### **分类算法（Classification Algorithms）**

**定义**：一种监督学习方法，通过已知标签的样本训练模型，预测新样本的类别（离散标签，如 “spam/non-spam”“ 疾病 / 健康 ”）。  
**常见算法**：

  

- 逻辑回归（二分类，输出类别概率）；
- 决策树（基于特征阈值划分，可解释性强）；
- 随机森林（多个决策树的集成，降低过拟合）；
- 支持向量机（SVM，寻找最优分类超平面）；
- 神经网络（如深度学习模型，处理复杂特征）。  
    **评估指标**：准确率、精确率、召回率、F1 分数、混淆矩阵等。



### 平衡策略对比

| 方法           | 优点                  | 缺点                                  |
| ------------ | ------------------- | ----------------------------------- |
| 加权损失函数       | 无需修改数据，计算效率高        | 可能无法完全解决特征分布不均                      |
| 过采样（如 SMOTE） | 增加稀有类样本多样性          | 计算开销大，可能引入噪声                        |
| 欠采样          | 减少多数类样本，加速训练        | 丢失多数类信息                             |
| 分层采样         | 确保每个 batch 中各类别比例均衡 | 仅适用于在线学习或深度学习                       |
| 数据增强         | 基于已知特征规则扩展样本        | 依赖人工经验,人工生成成本高、效率低，且难以覆盖所有模式,可能引入偏差 |

| 方法         | 核心逻辑                     | 与人工生成的关系                    |
| ---------- | ------------------------ | --------------------------- |
| 加权损失函数     | 训练时提高稀有类的 loss 权重，强迫模型关注 | 不改变数据分布，通过损失调整模型关注力         |
| 过采样（SMOTE） | 基于近邻特征合成新样本（机器自动）        | 人工生成是 “规则驱动”，SMOTE 是 “数据驱动” |
| 欠采样        | 减少多数类样本，平衡数据分布           | 不增加样本，而是减少其他类样本             |
| 分层采样       | 保证训练 / 测试集中类别比例一致        | 不改变原始数据总量，仅调整采样比例           |
| **人工生成**   | 基于规则手动扩展稀有类样本            | 直接增加稀有类样本量，属于 “主动扩充”        |

###### 无监督分类生产环境性能判断

场景: 在生产环境中，当模型上线后，实际输入的数据分布常常会与训练时不同,导致模型的识别效果下降（即“概念漂移”或“数据漂移”）
解决方式:
1. 生产环境特征监控: 对比生产环境新数据与训练集（或验证集）在关键特征上的分布差异 
	1. 常用指标: 均值与方差, 分桶频率, KL散度 / JS散度 ,熵值检测
	2. 对输入特征进行无监督异常检测（如孤立森林、One-Class SVM），若生产数据中异常样本比例激增，可能影响模型泛化。
2. 预测分布监控,针对生产环境中模型输出的预测分布
	1. 类别分布,如果某些类别显著增多或减小，说明模型的判别边界可能发生偏移。
	2. 置信度分布监控,置信度间隔监控,  如果置信度整体变得很低（比如中位数从 0.85 降到 0.60），表示模型对新数据不再“自信”，可能意味着效果在下降。
3. 测试数据复检: 在发布时保留一小部分“静态校验集”（可以是从历史数据中随机抽取并真实打标签的少量样本），可以不定期（每日/每周）用模型对它们做预测
4. 人工抽样复检: 在业务允许范围内，定期抽样一批生产样本，请人工快速标注（即“主动学习”），用这些带标签的数据评估当前模型的**精度/召回**等指标。如果这几个指标显著低于上线初期水平（或阈值），说明模型性能退化，需进行模型重训/调优。
5. 结合业务场景: 模型往往与具体业务目标紧密关联，直接观察业务层面的关键指标往往比仅看预测分布更有说服力, 通过观察 转化率,点击率,转单率,错误率等业务指标
6. 线上自动化监控框架 : **Metric 和 Dashboard**,**ML Monitoring 平台**
合理处置 :  **诊断并定位漂移来源**, **定期/周期化重训**, **灰度发布与回滚**,设置合理的AB测试场景

> 无监督检测本身并不能给出“绝对准确率”，只能说明“模型在新数据上更不自信、或检测到特征漂移”。要得到真正的准确度指标，仍需**定期或抽样收集人工标注**，或通过对小规模用户流量进行 A/B 测试与人工审核来定期校验。
