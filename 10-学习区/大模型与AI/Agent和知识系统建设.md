**人智协同优化：规则与算法的融合策略**

“人智”结合是我们目前正在探索的优化方向，核心可以理解为让LLM写优化方法，比如对某个数据源的智能分块或智能数据清洗方法，然后人工“微调”大模型提出的优化方法并人工落地优化方法。
“人智”结合的好处是既可以利用LLM的智能分析和推理能力，又可以通过人工“微调”大模型提出的优化方法来最大程度的避免LLM的幻觉，并减少LLM推理消耗的资源。

Query智能处理：复杂查询的语义理解与改写

如存在查询query很复杂、query拼写错误和语法错误。受限于业务方的表达能力和主动性，质量较差的query在线上一直存在，质量较差的query会影响召回相关性和准确性。


Query假设答案、多角度Query重写、Query分解和query纠错等query改写优化能力，优化查询知识系统的query质量


先让LLM生成一个假设性答案（如“API是应用程序编程接口，用于不同软件间通信...”），再用此答案去检索知识库——相当于把模糊提问“翻译”成专业表述。


多角度Query重写模式根据原始query从不同角度生成多个版本的新query，用以提升query的质量，然后用生成的新query进行向量检索，所有query检索出来的答案进行统一重排截断。多角度Query重写适用于探索性查询，提升召回多样性。


如果查询query很复杂，检索效果可能较差。例如“Langchain和LlamaIndex哪个框架在Github上的star更多？”，这个问题不太可能在语料库中找到直接比较，因此将这个问题分解为有意义的两个子查询：

子查询1: “Langchain 在 Github 上有多少star？”
子查询2: “Llamaindex 在 Github 上有多少star？”
两个子查询将并行执行，然后将检索到的上下文合并到一个提示中，输入到生成模型中。


利用LLM对query中的拼写错误或语法错误进行纠正，用纠正后的结果作为新的query查询知识系统以提高检索准确性。

检索精度提升：doc与query相关性对齐方法

“每次查询知识系统检索多少个doc效果是最优的？”这是一个超参数问题。线上很容易出现RAG检索出的结果，既包含相关结果，也包含无关结果。“水文占满窗口”将导致生成答案偏离主题、关键信息被淹没，降低用户满意度。
我们针对RT不敏感或技术能力不强的场景，比如答疑知识库，建设了上下文过滤能力，RAG检索的结果，送入生成模型之前，从RAG检索的内容中筛选出与query相关的token。这意味着只有与任务最相关的信息被保留，而其他不太重要的信息则被过滤掉。过滤有助于去除噪声和不相关的信息，使得模型能够更专注于对任务有用的信息。
通过减少发送的结果数据, 也就是上下文过滤, 提高了检索结果的相关性，生成模型生成的答案更简洁、更切题。



评测模块建设


针对向量的RAG评测
向量RAG评测框架使用的是Ragas评测框架，Ragas支持召回阶段、生成阶段的分开评测以及召回阶段+生成阶段的端到端全链路评测, 可以输出 衡量答案是否胡编乱造,衡量答案是否答非所问,找的资料全吗？,找的资料准吗？

针对GraphRAG的评测


图谱RAG使用嵌入模型进行实体Entity聚簇，使用LLM进行三元组relation的提取生成。为了针对不同业务选择对应场景最优的嵌入模型和LLM,

GraphRAG-Benchmark评测框架
包括四个难度层级的查询query:
级别1:基础事实；
级别2:关系推理；
级别3:上下文整合；
级别4:创造性应用
支持图谱相关评价指标，比如组织度（图中非孤立节点比例）直接反映图谱构建质量；支持检索阶段和生成阶段分阶段评估，利于定位问题是图没建好？还是没查好？还是没生成好？
