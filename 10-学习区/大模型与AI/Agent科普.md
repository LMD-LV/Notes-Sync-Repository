
**Agentic (智能体式/能动式)** 是一个**形容词**，指一种**特性或工作方式**

- **Agentic**：形容这个员工有**内驱力和自主判断力**。他不是只会等指令的“工具人”，而是会主动理解目标、自己想办法、规划步骤、调用资源，并在遇到困难时自行调整。


Linter 是一种检查代码是否违反规则的自动化工具。这里的“自定义”是说，你给它规定了特殊的、跟自家项目架构有关的规矩。





1. **通用 / 轻量 Agent：不需要训练，纯应用组装**
    
    个人使用、小场景落地的 Agent 几乎都属于这一类：用提示词定义角色、对接几个工具 API、配上 RAG 知识库即可使用。全程不涉及模型训练，就是纯粹的应用层开发。


1. **工业级 / 生产级 Agent：通常会配合训练优化**
    
    企业级生产环境的 Agent，为了保障稳定性、准确率和性能，往往会加入训练环节：

- 对基座做轻量微调，提升任务规划、工具调用的准确率
- 训练专属的技能模型、路由模型
- 用用户真实交互数据做持续迭代微调
    
    这时的 Agent 就不只是 “应用”，而是 “模型训练 + 应用调度” 的完整系统。



轻量Agent
（比如基于提示词搭建的 GPTs、用开源框架快速拼装的简易 Agent）,它的 Skills（技能 / 工具）确实是**推理运行时才调用**的

- 本质是 “大模型 + 工具插件 + 提示词规则” 的应用组装
- 模型本身不做任何训练，只是在接收到请求时，通过提示词引导它判断 “是否调用工具、调用哪个工具、如何传参”
- 这类 Agent 完全属于应用层开发，不涉及模型训练，和你原本的认知完全一致。




1. **训练模型 “调用技能的能力”（SFT 微调）**
    光靠提示词引导模型调用工具，在格式准确率、容错率、复杂场景稳定性上都有上限。工业级落地时，会用大量「用户请求 → 标准技能调用格式 → 执行结果」的标注样本，对基座模型做**监督微调（SFT）**。
- 训练的不是技能本身，而是模型调用技能的熟练度和准确率
- 训练完成后，模型在推理时调用同类技能会更稳定、更少出错
- 这是最常见的 “技能 + 训练” 关联场景。

2. **技能模块本身就是训练出的专项模型**
    
    很多专业 Agent 的 “技能” 不是简单的外部 API 调用，而是一个独立的专项小模型：比如专门做合同要素提取的技能、专门做工业缺陷识别的技能、专门做复杂数学推理的技能。

- 这个技能模块本身是通过训练得到的
- Agent 只是在运行时调用这个已经训练好的技能服务
- 这里的 “训练” 是技能本体的训练，不是 Agent 调度逻辑的训练


3. **技能路由 / 检索模型的训练**
    
    当 Agent 的技能库规模很大（几十上百个技能），靠大模型自行筛选技能效率低、误选率高。这时会专门训练一个**技能路由模型**，或者训练对应的 Embedding 向量模型，用来快速匹配用户请求和对应技能。

- 训练的是 “帮 Agent 快速找到正确技能” 的中间模块
- 属于 Agent 系统的训练环节，但不是大模型本身的全量训练。

4. **把外部技能 “内化” 进模型的训练**
    
    有些高频核心技能，外挂调用成本高、响应慢，就会通过训练把这项能力直接内化到大模型里。比如原本是外挂的 “代码解释器技能”，经过专项训练后，模型自身就能直接生成可执行代码、完成简单数值计算，无需再调用外部工具。

- 相当于把 “外部外挂技能” 变成 “模型自带原生能力”
- 这也是 “技能训练” 的典型含义之一。




**Hooks 系统是一套在 Agent 运行的关键节点上，强制执行的、不与模型大脑直接交互的自动化检查与拦截程序。**
