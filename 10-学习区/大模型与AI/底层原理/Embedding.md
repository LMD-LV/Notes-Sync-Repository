

模态对齐
不同模态的特征映射到同一个空间


给模型一批「语义相似的文本对（正样本）」和「语义无关的文本对（负样本）」，让模型通过 “对比” 自动学会规律 —— 语义相关的文本，向量要尽可能接近（强关联）；语义无关的文本，向量要尽可能远离（弱关联 / 无关联）


RAG 里的 encoder-only embedding 模型
核心作用是把一整段话（用户 query、文档段落）压缩成一个固定长度的向量，用这个向量代表整段话的语义。


原生的 encoder-only 预训练模型（比如原始 BERT），是靠「掩码语言模型（MLM，猜被遮住的字）」训练出来的，它的优化目标是 “字词级别的语言理解”，**不是 “衡量两段话的语义相似度”**。直接拿原生 BERT 的 CLS 向量做检索，效果会很差，因为它的向量空间从一开始就不是为 “匹配相似度” 设计的。


需要**针对 “语义检索” 这个目标，再单独微调一遍这个 encoder**，而对比学习就是目前做这件事最主流、效果最好的训练范式。



## Embedding 的 “语义” 是怎么训练出来的？

最开始的时候，Embedding 矩阵里的数值都是**随机初始化**的，每个词的向量都是乱的，根本没有语义。

语义是在整个模型的训练过程中，自动学出来的：

1. 模型拿句子做训练（比如预测下一个词），比如句子「我吃苹果」；
2. 模型通过 Embedding 查表，拿到每个词的向量，送入后续网络计算；
3. 如果模型预测错了（比如预测下一个词是 “桌子”），就会产生损失；
4. 损失通过反向传播，**倒回来更新 Embedding 矩阵里的数值**；
5. 训练久了，模型就会发现：「苹果」和「香蕉」经常出现在相似的语境里（都能跟在 “吃” 后面），于是它们的向量就会慢慢靠近；而「我」和「苹果」语境差很远，向量就会离得远。

最终，整个 Embedding 矩阵就形成了一个**语义空间**：意思相近的词聚在一起，意思不同的词离得很远。


## Embedding 层的完整逻辑链是这样的

我把从 Token ID 到最终向量的完整路径给你串起来，中间没有任何跳步：

1. **第一步：文本 → Token ID**
    
    Tokenizer 把 “苹果” 变成编号 2。这一步只是给词起个 “数字名字”，单个整数没法直接算。
    
2. **第二步：Token ID → One-Hot 向量（逻辑上存在，工程上不真的生成）**
    
    把编号 2 转成 4 维的独热向量 `[0, 0, 1, 0]`。
    
    这一步解决了 “离散整数不能做矩阵运算” 的问题，但带来了维度爆炸、无语义的新问题。
    
3. **第三步：One-Hot 向量 × Embedding 权重矩阵 → 低维稠密向量**
    
    用高维的 One-Hot 向量，去乘以一个可训练的 V×d 权重矩阵，得到一个 d 维的稠密向量。
    
    - 数学上：这是一次线性投影，把 V 维空间的点，映射到 d 维空间里；
    - 效果上：维度从 V 降到了 d，解决了维度爆炸；
    - 训练上：这个权重矩阵的参数是跟着整个模型一起学习的，慢慢就会把语义相近的词映射到空间中相近的位置，解决了无语义的问题。
    
4. **工程优化：用 “查表” 代替 “矩阵乘法”**
    
    既然我们已经知道 “One-Hot 乘矩阵 = 取矩阵的对应行”，那工程上就根本没必要真的生成 One-Hot 向量、再做完整的矩阵乘法 —— 直接拿着 Token ID，从 Embedding 矩阵里把对应行的向量取出来就行。
    
    这个操作就叫「查表（Lookup Table）」，速度快、省显存，是所有深度学习框架里 Embedding 层的真实实现方式。


### 三、RAG 场景里，正负样本具体是什么？

在 RAG 检索模型的训练中，正负样本有明确的业务含义，常见构造方式如下：

#### 1. 正样本对（应该建立强关联）

指语义匹配、query 可以被这段文档回答的文本对，常见构造方式：

- **有监督场景**：人工标注的「用户问题 - 对应答案段落」对；或者自动挖掘的问答对（比如社区问答的问题和最佳回答）。
- **无监督场景**：同一句话经过轻微扰动（比如模型内部随机 dropout、同义词替换、语序微调）得到的两个句子，互为正样本（经典的 SimCSE 无监督方案就是这么做的）。

#### 2. 负样本对（应该弱关联 / 无关联）

指语义不相关、无法回答 query 的文本，常见构造方式：

- **批次内负样本（Batch Negatives）**：训练时一个 batch 里有 N 个 query+N 个正文档，每个 query 把剩下 N-1 个文档都当成负样本。这是工业界最常用的技巧，效率极高，不用额外构造数据。
- **随机负样本**：从整个文档库里随机抽其他不相关的段落，和当前 query 组成负样本对。
- **难负样本**：和 query 语义有部分重合、但实际不能回答问题的文档（比如 query 是 “西红柿鸡蛋汤做法”，负样本是 “西红柿炒鸡蛋做法”），这种负样本能倒逼模型学更精细的语义区分，提升检索精度。
