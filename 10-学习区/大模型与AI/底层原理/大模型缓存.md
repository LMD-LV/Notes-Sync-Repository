缓存命中，**本质是自注意力机制中的 KV 缓存（Key-Value Cache）复用**，属于**推理阶段的计算优化手段**—— 它缓存的是「中间计算结果张量」

大语言模型是**自回归生成**的：每生成 1 个新 token，都需要把「历史所有 token（输入提示词 + 已生成内容）」输入模型，计算一次自注意力，再预测下一个 token。

如果不做缓存，会出现一个严重的算力浪费：

- 生成第 1 个 token：计算前 N 个 prompt token 的 K、V
- 生成第 2 个 token：重新计算前 N+1 个 token 的 K、V
- 生成第 3 个 token：重新计算前 N+2 个 token 的 K、V
- ……

你会发现：**前面已经算过的 token，它们的 K、V 值从头到尾都不会变**—— 因为 token 本身没变，模型的权重参数也没变，投影计算的结果必然是固定的。每次都重算，就是纯纯的冗余计算。

KV 缓存就是为了解决这个冗余而生的。

：缓存的不是 \(W_K, W_V\) 权重矩阵，而是「输入 token 经过权重投影后的结果张量」。权重矩阵本来就一直在显存里，不需要缓存。

KV 缓存是**推理中间结果**，是输入文本经过 \(W_K, W_V\) 投影后的张量，随输入变化而变化，是缓存的主体

节省了算力,降低了延迟,提升了显存的占用



提示词缓存

行业里一般叫 **Prefix Caching（前缀缓存）** 或 **Prompt Caching**，它是 KV 缓存的延伸，本质是**跨请求复用相同前缀的 KV 结果**。
服务端会把「常用前缀文本 → 对应的多层 KV 张量」提前计算好，存在全局缓存池里。当一个新请求进来时：
- 先匹配请求的前缀和缓存里的前缀是否完全一致
- 如果匹配上（命中），就直接复用缓存里的前缀 KV，**只计算新增的、不重复的那部分文本的 KV**
- 如果没命中，就从头计算全部 KV
比如：系统提示有 2000 token，用户提问有 100 token。
- 无缓存：需要计算 2100 个 token 的 KV
- 命中前缀缓存：只需要计算 100 个 token 的 KV
前缀越长、复用率越高，节省的算力就越夸张。

前缀缓存是**精确字符级匹配**—— 差一个字、一个标点、一个空格，从差异位置之后的 KV 就全部失效，无法复用。这和训练数据里有没有出现过这段话没有任何关系。



### 1. 输入的矩阵（Input Matrix）

**用户送入模型的原始特征数据张量**

- LLM 场景：prompt 经过 embedding 得到 `[batch, seq_len, hidden_dim]` token 特征矩阵
- 多模态 VQA：图片 Patch 向量 + 文本 token 拼接后的输入矩阵
- 本质：**动态数据，每次推理都不一样；存在显存 / 内存，前向计算源头**

举例：提问 `请分析这份报表`，文字转成向量形成的矩阵。

### 2. 有效数据（Mask / 有效序列掩码矩阵）

全称：有效位置掩码矩阵

大模型序列长度参差不齐，一条 batch 里多条句子长短不一：

短句子末尾填充占位符（padding token）。

**有效数据矩阵 = 标记哪些 token 是真实内容、哪些是无效 padding**

- 有效值 = 1：真实文字，参与注意力计算
- 值 = 0/-inf：padding 占位，需要屏蔽、禁止参与计算

👉 作用：防止模型把空白填充当成有效信息，

解决**上下文 padding 干扰、序列长度不一致**问题。

> 很多人口语简化直接叫「有效数据矩阵」。

### 3. 入参出参（权重矩阵，Parameter Matrix）

也就是你之前理解的**模型权重（W）**

- 入参：线性层输入投影权重（Wq/Wk/Wv、FFN 权重）
- 出参：输出变换权重、最后的 lm_head 词表投影矩阵
    
    **关键特征：推理全程固定不变，保存在权重文件 safetensors/bin 里面；训练阶段才更新。**

> 大白话类比整条流水线：
> 
> **输入矩阵 = 原材料（每次不一样）
> 
> 有效数据掩码 = 分拣规则：区分有用原料和垃圾填充物
> 
> 入参出参权重 = 机器内部固定模具、加工规则（模型学到的知识）**

## 三者本质最核心区别（非常关键）

1. **输入矩阵：动态样本特征（每次推理都会变）**
2. **有效数据（掩码矩阵）：动态约束条件（随每条样本长度变化）**
3. **入参出参权重：静态模型参数（模型出厂就确定，推理不改动）**
