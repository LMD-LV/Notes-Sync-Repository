
### 1. 上下文瓶颈
**典型问题**：多轮对话遗忘前文、长文档无法一次性处理、指令遵循漂移。

| 缓解方案 | 说明与适用场景 |
|---------|---------------|
| **滑动窗口/摘要压缩** | 用滑动窗口保留最近 N 轮对话；对更早历史用摘要模型生成压缩记忆。适合客服、多轮问答。 |
| **关键信息槽位填充** | 维护一个结构化状态字典（如槽位：目的地、日期），对话中不断更新，将结构化状态注入 Prompt。适合订票、填表类 Agent。 |
| **分块-递归摘要** | 长文档分成 chunk，每个 chunk 独立摘要，再摘要摘要，形成多层摘要树；检索时根据问题召回相关摘要和原始块。适合超长文档问答。 |
| **记忆增强检索（Mem-RAG）** | 将历史交互写入外部记忆库（向量库或知识图谱），每次对话查询时动态检索相关历史，构造上下文。适合需要长期记忆的 Agent。 |
| **长上下文模型直接使用** | 若成本可接受，直接选用 128K/1M 上下文窗口的模型（GPT-4 Turbo、Claude 3、Gemini 1.5 Pro），减少架构变通。 |

### 2. 推理瓶颈
**典型问题**：多步逻辑链断裂、数值计算错误、复杂规划失败。

| 缓解方案 | 说明与适用场景 |
|---------|---------------|
| **思维链（CoT）强提示** | 在 Prompt 中要求“让我们一步一步思考”，并提供 Few-shot 示例。几乎零成本提升推理。 |
| **自我一致性（Self-Consistency）** | 采样多条推理路径，取多数投票结果。代价是推理成本 ×N，适合对准确率要求极高的决策。 |
| **工具增强（Tool Use）** | 让模型将数值计算、日期换算、代码执行等交给计算器/解释器完成，模型只负责任务拆解与工具调用。Agent 场景标配。 |
| **ReAct / 计划-执行模式** | 强制模型交替输出“思考→行动→观察”，将复杂任务分解成原子步骤，结合环境反馈修正。适合 Agent 任务。 |
| **分层推理 + 验证器** | 生成初步推理后，再用一个轻量模型或规则对逻辑一致性、事实性进行校验，不合格则重试。适合对可靠性要求高的生产环境。 |
| **结构化输出引导** | 约束模型输出 JSON、决策树等格式，确保推理过程可解析、可干预，避免自由文本中的推理跳跃。 |

### 3. 幻觉瓶颈
**典型问题**：凭空捏造事实、引用不存在的来源、数据数值错误。

| 缓解方案 | 说明与适用场景 |
|---------|---------------|
| **严格检索增强（RAG）闭环** | 强制模型仅基于检索到的文本片段回答，并在 Prompt 中明确“如果找不到依据，就说不知道”。知识库问答的基本范式。 |
| **引用溯源与高亮** | 要求模型在回答中引用来源片段编号，前端展示时可点击验证；回答无引用则自动告警或拦截。 |
| **事实核验管线** | 将生成的陈述拆成原子事实，逐一与知识库或搜索引擎结果比对，不一致则自动修正或降权。适合高准确性场景。 |
| **拒答机制与置信度阈值** | 监控生成文本的 logprob 或不确定性度量，低于阈值时触发拒答或转人工。同时设置“安全回答”模板。 |
| **反事实数据微调** | 用含幻觉的样本和正确版本构造训练数据，对模型进行微调，教会模型说“我不确定”。需要构建标注数据。 |
| **多模型一致性检查** | 用另一个独立模型（甚至不同厂商）对同一生成内容做事实性判断，交叉验证。成本较高，适用于关键业务。 |

### 4. 检索质量瓶颈
**典型问题**：召回文档不相关、冗余、排序差，导致最终回答错误。

| 缓解方案 | 说明与适用场景 |
|---------|---------------|
| **混合检索 (Hybrid Search)** | 结合稠密向量检索（语义匹配）与稀疏关键词检索（BM25），取并集或加权融合，大幅提升召回率。RAG 系统几乎必配。 |
| **重排序模型 (Reranker)** | 召回后使用 Cross-encoder 模型对候选文档精细排序，保留 top-k，可显著提升精度。例如 Cohere Rerank、BGE-reranker。 |
| **查询改写与扩展** | 用 LLM 将用户问题改写成多个不同角度、不同关键词的子查询，分别检索再合并。适合模糊或简短查询。 |
| **文档结构优化与分块策略** | 用语义分块（按主题切分）替代固定长度切分；保留标题层级、添加元数据。从源头提升检索精度。 |
| **自我反思式检索** | 模型先生成初步答案，再根据答案中不确定的部分生成新的检索查询，进行第二轮补充检索。适合复杂多跳问答。 |
| **知识图谱辅助** | 将知识库中的实体、关系构建为图，检索时结合图遍历找到关联实体文档，提升召回全面性。适合有结构化关联的知识库。 |

### 5. 多模态瓶颈
**典型问题**：图表/PDF 信息提取不准、图文不对齐、跨模态推理弱。

| 缓解方案 | 说明与适用场景 |
|---------|---------------|
| **文档解析 + 视觉描述生成** | 用 OCR 提取文字，用版面分析识别表格、图片，并对不可读图片调用视觉模型生成自然语言描述，将多模态统一为文本，送入纯文本 RAG 流程。适合 PDF 分析。 |
| **多模态嵌入与检索** | 使用 CLIP 等多模态模型将图片和文本映射到同一向量空间，直接实现“用文本搜图/用图搜文”，再结合视觉问答模型解读。适合图文知识库。 |
| **截图+视觉模型直接问答** | 对于仪表盘、图表等，直接截图送入 GPT-4V 等视觉语言模型，让其分析趋势、提取数据。无需复杂的前处理管线。 |
| **跨模态对齐校验** | 在图文智能分析中，单独提取文本关键声明和图片关键描述，用规则或模型比对二者是否一致，不一致时标记人工复核。 |
| **多步多模态工具链** | 将复杂图文分析拆成：OCR → 数据提取（如表格识别）→ 代码解释器绘图/计算 → 文本模型解读，串联成流水线。 |
| **针对领域的微调多模态模型** | 当通用模型对专业图表（如工业图纸、医学影像）识别不佳时，采集领域数据进行微调，如 CogVLM 微调、LLaVA 微调。 |

---

**总体落地建议**：
- 这五个瓶颈很少孤立出现，实际项目往往需要用 **RAG + Agent + Guardrails** 的组合架构来系统应对。
- 可以从 **“检索质量 + 幻觉”** 这对强耦合点开始治理，因为它们是知识库问答的底线。
- 推理瓶颈和 Agent 设计强相关，引入工具和 ReAct 模式后，上下文管理会变得更复杂，需提前规划记忆架构。
