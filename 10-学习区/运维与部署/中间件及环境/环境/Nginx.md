#### 通识

-   nginx是轻量级的 Web 服务器/反向代理服务器及电子邮件（IMAP/POP3）代理服务器，作为http代理服务器对外提供服务，负载均衡做的很好，高并发的性能最多支持五万个连接，处理静态文件，索引文件以及自动索引；打开文件描述符缓冲。无缓存的反向代理加速，简单的负载均衡和容错，非常高效的反向代理、负载均衡服务器，支持内核 Poll 模型
-   Nginx 采取了分阶段资源分配技术，使得它的 CPU 与内存占用率非常低。Nginx 官方表示在保持 10,000 个无活动连接时，它只占 2.5M 内存，所以类似 DOS 这样的攻击对 Nginx 来说基本上是毫无用处的
-   常见的使用场景为 代理，负载均衡，动静分离
-   默认安装的地址 usr/local
-   一个完整的服务，由mater 和 worker组成，具体的连接由wroker处理，每个worker单独处理连接
-   多个wroker 可以实现热部署，每个都是独立的进程，某个出现问题，将由其余的worker争抢请求，使服务不中断
-   在配置文件的全局块中 通过wroker\_processes设置wroker的个数，建议与服务器的cpu数相同
-   建立连接请求的时候，可能会占用 2，4个连接数，

-   访问静态资源一般是2个，http一般是4个
-   入站，出站 需要两个连接，如果是4个，可能是出现了三次握手链接，长链接维护，额外链接等

-   nginx服务的进程号存储在pid文件中
-   发布新的配置文件之前，支持测试，如果采用从容的方式关闭，然后启动新的服务(-s quit 优雅关闭(会保存相关信息)，会使用旧的配置文件提供请求，当请求结束后，切换到新的配置文件，来实现。nginx -s stop 由快速关闭(不保存相关信息，迅速终止)，)
-   使用k代表千字节，m代表万字节

#### 配置相关

-   配置文件中的内容 包含三部分内容

-   全局块：配置服务器整体运行的配置指令 ，比如 worker\_processes 1;处理并发数的配置
-   events 块：影响 Nginx 服务器与用户的网络连接 比如 worker\_connections 1024;，具体选择的网络IO模型
-   http 块 ，用于配置具体的请求转发，内含 server，http块

-   每个 http 块可以包括多个 server 块，而每个 server 块就相当于一个虚拟主机
-   而每个 server 块也分为全局 server 块，以及可以同时包含多个 locaton 块
-   **server 块** 中最常见的配置是本虚拟机主机的监听配置和本虚拟主机的名称或 IP 配置

###### 支持功能

-   get方法可能读取的是缓存下的数据，可以设置不同的缓存级别，如，任何缓存区可缓存，个人缓存区，不能缓存，
-   可以针对ip地址做，限制，放行，限制访问的频率，限制访问的并发数，限制连接的速率(带宽)
-   可以设置 访问的用户身份密码
-   不同的文件的权限
-   支持将协议升级，从http升级成为https
-   在处理静态数据时，针对不同的资源，也可以设置不同的过期时间，如果没有过期服务端返回304，过期了会重新请求服务端
-   可以记录下，客户端的名称，浏览器的相关信息，跳转过来的上一个网页的链接地址，

###### 代理配置

-   正向代理， 它隐藏了真实的请求客户端，服务端不知道真实的客户端是谁，客户端请求的服务都被代理服务器代替来请求。需要在客户端配置代理服务器进行指定网站访问，VPN
-   反向代理，反向代理隐藏了真实的服务端，对于客户来说不知道访问的是哪台服务器。暴露的是代理服务器地址，隐藏了真实服务器 IP 地址
-   通过是不是要客户端配置代理，来确定正向，反向

```plain
------------location的路径配置
# 示例配置
location /app/ {
    # 匹配以/app/开头的路径
}

location /app {
    # 匹配以/app开头的路径
}

------------proxy_pass的路径配置
# 不带/
location /app {
    proxy_pass http://backend;
    # 请求/app/test 会代理到 http://backend/app/test
}

# 带/
location /app/ {
    proxy_pass http://backend/;
    # 请求/app/test 会代理到 http://backend/test
}
保持location和porxy_pass 路径一致性很重要
```

###### 动静分离

-   将静态资源交给nginx管理，放置在不同的目录下，正则匹配指到对应的目录下，Tomcat 处理动态页面
-   动静分离从目前实现角度来讲大致分为两种，

-   一种是纯粹把静态文件独立成单独的域名，放在独立的服务器上，也是目前主流推崇的方案
-   另外一种方法就是动态跟静态文件混合在一起发布，通过 nginx 来分开。
