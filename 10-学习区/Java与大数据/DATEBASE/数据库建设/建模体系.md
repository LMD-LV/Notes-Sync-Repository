1.  在订单和商品的映射关系中，可以使用 多对一(商品看订单)，一对多(订单看商品)，但是考虑到存储的空间，计算的速度，还是在商品的维度看，多个商品对一个订单，每个商品的info添加一个字段即可，如果是 订单维度做存储订单下的所有商品，得用列表的方式来实现，计算和存取都会慢
2.  多对多，表中的字段设计复杂，可以引入第三张表
3.  函数依赖，相当于y=fun(X)，完全函数依赖就是从X得Y，部分函数依赖就是从X中的部分字段得Y，传递函数依赖就是X相当于一个推导式，有传递的过程
4.  第一范式，属性不可切分，细化属性，例如 将地址拆 成 省 城 区 街道 ....

1.  第二范式，不能存在部分函数依赖
2.  第三范式，不能存在传递函数依赖

5.  维度模型，分为事实和维度，

1.  事务型事实表， 最细粒度，事务围绕业务过程展开
2.  周期快照事实表，解决状态性，按照一个时间周期展开 累积性 的统计指标
3.  累积快照事实表，一个完整流程中的多个业务过程，主要是通过时间标识关键业务步骤
4.  维度表，

1.  维度字段过少，直接放到事实表中，就叫做维度退化。
2.  规范化的设计就是雪花模型，反规范化就是星型模型
3.  维度变化，属性随着时间变化，引出 全量快照表，拉链表(本质就是数据的有效期)
