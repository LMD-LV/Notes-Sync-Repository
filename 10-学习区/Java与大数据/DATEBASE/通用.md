-   数据库实例通常指的是在内存中运行的数据库服务进程，它管理数据库文件，处理客户端连接，执行查询等。
-   事务能否跨越实例，看数据库的设计，单实例事务(InnoDB)无法跨越，通过外部事务管理器(SEATA)，协调器等实现跨实例事务
-   行锁和表锁都无法跨实例，得记住分布式锁等协调对数据的操作
-   jdbc是一套规范，由数据库厂家实现(mysql-connector-java),JDBCTemplate是spring对JDBC的上层封装，便于操作
-   数据库的常见优化点,

-   连接池,最小化事务日志,延迟索引,并行处理,批量提交, 数据库的原生工具

-   数据加载中的优化点, 内存数据映射, 并行处理, 缓冲区管理, 原生工具, 绕开SQL引擎的开销
-   存算分离,存算一体框架的优缺点
-   update 和 upsert 的区别
-   数据库日志 ,可以用于恢复数据, 但是大批量日志写入会影响性能, 通过 日志存储在内存中, 批量日志模式来减少写入次数
-   最小化事务, 通过合并事务, 减少日志的持续时间, 尽快提交日志 ,减少涉及事务的数据量
-   数据库中的 dump 和 copy 一个是库级别的,导出涉及 索引,元数据,触发器等 一个是表级别的, 一般仅导出数据, 所以后者更快
-   对于数据量大的情况下，业务分库，主从复制，数据库分表

-   水平分表，将少用的列拆分出去
-   垂直分表，常见在两千万-五千万 时候注意分表，要求全局的id唯一

-   分布式主键生成算法，雪花算法，长度64位，由 符号位+时间戳(毫秒)+机器id(10位，1024个)+毫秒内的流水号(12位，4096个)，整个分布式内不会出现id重复
-   乐观锁，通过version判断是否被修改，
-   悲观锁
-   Navicat显示出来的实际数据量可能与实际的值不一致,原因是存储引擎的问题导致的,对于myISAM的引擎的结果是正常的,但是对于InnoDB类型的数据量会出现误差的情况
-   现代分布式数据库中，常见的数据分布方式有如下几种：Round-Robin、Range、List 和 Hash
