> [!note] 边界声明
> 本文是名词与经验清单;VO/DTO/POJO 等概念定义正本见 [[通识]](JAVA方向/web端/通识)。

-   web区分为cs模式，BS模式
-   项目开发 前后端不分离（jsp等后端动态页面技术） 分离：前端工程化，vue等动态页面技术
-   HTML框架，CSS美化，js动态处理页面
-   常见配置文件类型 properties XML，YAML，YML，JSON
-   常见的web服务器 tomcat，jetty等，默认8080端口，web.xml中mine类型，作用为通知客户端，接收到的是什么类型的文件
-   tomcat端口后的 名称 即为项目部署的web_exploed名称
-   http中的 报文，请求，响应 ，都由 行头体 组成个
-   资源 分为 静态（运行前）, 动态 资源，静态资源和动态资源确实都遵循"路径定位 + 请求 + 响应"的基本模式，访问路径就是资源的唯一标识符
-   服务器返回的response中通过MIMIE类型，让浏览器明确返回的是什么类型的数据，怎么打开
-   常见的乱码问题：字符集的设置问题，ASCII为最底层的字符集，charset中的参数，将决定浏览器的参数编码，如果和tomcat解析参数使用字符集不一致将出现乱码问题
-   路径在不同的协议下代表不同，file代表本地，http代表url
-   路径分为相对（./ 开头，但是通常省略），绝对路径（需要加上项目名称），
-   为了适应项目的上下文路径的变化，可以将项目的上下文路径变成 /. 缺省的方式，或者每次调用getContextpath方式获取最新的上下文路径
-   VO对象，POJO对象，Bean对象，Entity对象（通常对应表）
-   会话技术的实现，通过cokkie和session共同实现，前者保存在浏览器端，后者在服务器端，cokkie是由客户单第一次请求后，服务器端生成在response中返回，后续请求中放在request中，session的id，jsession按照cookie的方式放入响应体，客户端凭此寻找对应的session
-   cookie 的实效分为 会话级（客户端的内存中） 持久化 （客户端的磁盘中），sesison是直接设置时效
-   Cookie支持按照不同的请求路径使用不同的cookie
-   会话域和session中的有效期有关( 会话在用户不活动一段时间或显式结束会话时结束),与Jsession相关,每次请求将重新生成一个请求域,,应用域中数据会在服务被销毁的时候结束
-   作为动态加载，ajax是一种通过xmlhttprequest等技术实现向服务器请求资源，动态加载
-   跨域，前后端分离，客户端向前端服务器，后端服务器 获取数据，但是两个服务 不在同源（**同源策略会阻止一个域的javascript脚本和另外一个域的内容进行交互。所谓同源（即指在同一个域）就是两个页面具有相同的协议（protocol），主机（host）和端口号**）
-   常见的跨域解决方式 1， 前端服务器反向代理请求到后端服务器 2，后端配置跨域过滤器
-   MVC中的mapping地址, 通过注释的方式 ,最后的路径可以加上 / , 浏览器不加 最后的/ 可以访问,如果浏览器加上了最后的/,因为路径问题会被直接跳转到error页面, 微服务调用的时候同理,不可以在最后加/
