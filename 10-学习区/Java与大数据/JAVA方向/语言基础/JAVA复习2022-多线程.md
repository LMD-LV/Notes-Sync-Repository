#### Thread类

*\* 类的位置  
**\* java.lang  
**\* 类的特点  
**\* 针对线程开启和操作的工具类  
**\* 类的构造器  
**\* public Thread()  
**\* 分配新的 Thread 对象。  
**\* public Thread(String name)  
**\* 分配新的 Thread 对象。  
**\* public Thread(Runnable target)  
**\* 分配新的 Thread 对象  
**\* public Thread(Runnable target,String name)  
**\* 分配新的 Thread 对象。  
**\* 类的方法  
**\* public static Thread currentThread()  
**\* 返回对当前正在执行的线程对象的引用。  
**\* public final String getName()  
**\* 返回该线程的名称。  
**\* public static void sleep(long millis)  
**\* 在指定的毫秒数内让当前正在执行的线程休眠（暂停执行），此操作受到系统计时器和调度程序精度和准确性的影响  
**\* public void start()  
**\* 使该线程开始执行；Java 虚拟机调用该线程的 run 方法。  
**\* public void run()  
**\* 如果该线程是使用独立的 Runnable 运行对象构造的，则调用该 Runnable 对象的 run 方法；  
**\* 否则，该方法不执行任何操作并返回。 Thread 的子类应该重写该方法。

#### 线程

**  

线程安全问题  
* 1.出现了不存在的数据  
* 2.出现了重复数据  
  
  
  
线程安全的解决方案  
* 1.同步(synchronized)代码块  
* 2.同步方法  
* 3.Lock锁(暂不涉及)  
*  
* 同步代码块:  
* 格式:  
* synchronized (同一资源对象) {  
* 可能出现线程安全问题的代码  
* }  
* 解释:  
* 同一资源对象(要求每个线程是同一个对象):  
* 如果多条线程处理同一资源,且每条线程的处理动作完全相同,同一资源对象其实就是执行动作对象  
* 如果多条线程处理同一资源,且每条线程的处理动作完全不同,同一资源对象其实就是处理同一数据对象  
* 如果多条线程处理同一资源,且每条线程的处理动作涉及静态,同一资源对象其实就是当前类的字节码文件对象(Class类型)  
* 特点:  
* 当多条线程遇到同步代码块,需要多条线程抢夺同一资源对象,哪条线程抢夺到同一资源对象就会进入同步代码块,执行里面的内容;  
* 没有抢夺的同一资源对象的线程,在同步代码块外面进行等待进入线程释放同一资源对象进行抢夺  
* 位置:  
* run()中

  

  

*同步方法:  
* 格式:  
* 修饰符 synchronized 返回类型 方法名 () {  
* 可能存在线程安全的代码  
* }  
*  
* 特点:  
* 当多条线程遇到同步方法调用时,需要多条线程抢夺同步方法的调用权,因为同步方法在栈内存中不能出现第2块区域,哪条线程抢夺  
* 到同步方法的调用权,就会执行同步方法体中的代码;没有抢夺同步方法的调用权,在同步方法调用的外面进行等待当前同步方法出栈;  
* 位置:  
* 和run()在同一个类中  
* 前提条件:  
* 多条线程的执行动作相同*

*线程间通信(等待唤醒机制):  
* 将"生产者"线程和"消费者"线程建立通信联系,从而形成有规则的执行  
* "生产者"线程:负责生产资源的线程对象  
* "消费者"线程:负责消耗资源的线程对象  
*  
* Object类中线程的相关方法:  
* public final void notify()  
* 唤醒在此对象监视器上等待最长的单个线程。  
* public final void notifyAll()  
* 唤醒在此对象监视器上等待的所有线程  
* public final void wait()  
* 在其他线程调用此对象的 notify() 方法或 notifyAll() 方法前，导致当前线程等待  
*  
* 线程间通信的前提条件(三要素)  
* 同一资源  
* 生产线程  
* 消费线程*

*线程的状态和线程转换间的转换  
* 含义:  
* 线程状态就是线程在执行的过程中不同的状态  
*  
* 通过面向百度查询获取线程状态有N种  
* 5种(45%左右),6种(40%左右),7种(12%左右),其它(3%左右)  
*  
* 正确答案:  
* 6种  
*  
* 状态:  
* 新建(NEW):创建线程对象但并未开启线程的状态  
* 运行(RUNNABLE):线程对象正在运行的状态  
* 阻塞(BLOCKED):线程对象在运行的状态下遇到的线程安全,并未抢夺到资源对象  
* 无限等待(WAITING):线程对象被资源调用了wait()  
* 计时等待(TIMED_WAITING):线程对象被执行了sleep(),时间未到的状态  
* 终止(TERMINATED):线程正常执行完毕  
*  
* 线程间的转换:  
* 新建状态的转换关系:  
* 可以转换运行状态:当线程对象调用start()时;  
* 运行状态的转换关系:  
* 可以转换阻塞状态:线程对象遇到了线程安全,并未抢夺到资源对象  
* 可以转换无限等待状态:线程对象被执行了wait()  
* 可以转换计时等待状态:线程对象被执行了sleep()  
* 可以转换终止状态:线程对象正常执行完毕  
* 阻塞状态的转换关系:  
* 可以转换运行状态:其它线程对象释放资源对象,并且当前线程对象抢到资源对象  
* 无限等待状态的转换关系:  
* 可以转换运行状态:  
* 当线程被调用了notify()或notifyAll()时,如果有线程安全,线程对象抢夺到其它线程释放的资源对象  
* 当线程被调用了notify()或notifyAll()时,如果没有线程安全,线程对象直接转换为运行状态  
* 可以转换阻塞状态:  
* 当线程被调用了notify()或notifyAll()时,线程对象遇到了线程安全,并未抢夺到其它线程释放的资源对象  
* 计时等待状态的转换关系:  
* 可以转换运行状态:  
* 当等待时间已到,如果有线程安全,线程对象抢夺到其它线程释放的资源对象  
* 当等待时间已到,如果没有线程安全,线程对象直接转换为运行状态  
* 可以转换阻塞状态:  
* 当等待时间已到,线程对象遇到了线程安全,并未抢夺到其它线程释放的资源对象  
*  
*  
* 聊一聊网上的7种和5种线程状态说法:  
* 7种说法:新建,就绪,运行,阻塞,无限等待,计时等待,终止  
* 就绪:调用了start(),并未调用run()状态  
* 运行:调用了start(),且调用了run()状态  
* 5种说法:新建,就绪,运行,等待,终止  
* 将"阻塞,无限等待,计时等待"合并为"等待"
