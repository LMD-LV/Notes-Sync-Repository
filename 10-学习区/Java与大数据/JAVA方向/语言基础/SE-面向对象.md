## 面向对象

面向对象学习小技巧:

* 1.看有没有合适做事情的对象所对应的类

* 如果有,进行下一步

* 如果没有,自定义类

* 2.根据类创建或获取对象

* 3.根据对象调用方法

面向对象三大特征: 封装,继承,多态

类:是生活中一类事物属性信息和行为动作的统称

对象:是这一类事物的具体体现

关系:类是对象的模版,抽象 对象是类的实体,实例

类与对象的先后关系: 先类后对象

​  

#### 类的设计:

* 设计过程:

* 1.根据类的属性信息和行为动作设计出基础的类

* 2.在类中加入"封装"思想

* 3.在类中加入"构造器"概念

* 4.在类中加入特殊(静态)的属性信息和行为动作

* 5.将类一拆为多,加入"继承"思想

* 6.解决继承思想的安全解决,加入"抽象"概念

* 7.将多个类继续一拆为多,加入"接口"概念

* 8.在类或接口中加入"常量"概念

* 9.在类或接口中加入"嵌套"概念

* 10.在类中加入构造器代码块的概念

* 11.在类中加入静态代码块的概念

* 12.熟悉Java中特殊的类"枚举类"

* 分类:

* 测试类:基于测试效果演示的类(含有main()或者@Test)

* 标准类: 将类完整的设计出来

​  

* 解释:

* 属性信息 ==> 代码中的"成员量"

* 行为动作 ==> 代码中的"成员方法"

* 成员变量:在类中方法外的变量

* 静态变量:在类中方法外,且含有static关键字修饰的变量,静态变量归属于"类"(暂不涉及)

* 成员常量:(暂不涉及)

* 

* 成员方法:

* 实例方法:在类中没有static关键字修饰的方法,实例方法归属于"对象"

* 静态方法:在类中含有static关键字修饰的方法,静态方法归属于"类"(暂不涉及)

* 格式:

* public class 类名 {

* 实例变量

* 实例方法

* }

* 对象的创建:

* 格式: 类名 对象名 = new 类名();

局部变量和实例变量的区别:

* 局部变量:声明在代码块中或者代码块声明上的变量

* 实例变量:声明在类中方法外,且没有static关键字修饰的变量

* 区别:

* 代码中声明的位置不同:

* 局部变量:代码块中或者代码块声明上

* 实例变量:类中方法外

* 内存中存储的位置不同:

* 局部变量:栈内存

* 实例变量:堆内存

* 是否含有默认值不同:

* 局部变量:没有

* 实例变量:含有

* 代码中变量的作用域不同:

* 局部变量:所属方法中

* 实例变量:所属类中(静态方法,静态常量,静态代码块,静态成员内部类中无效)

* 内存中变量的生命周期不同:

* 局部变量:随着方法的调用而加载,随着方法的出栈而消失

* 实例变量:随着对象的创建而加载,随着对象的回收而消失

* 加载方式和次数不同:

* 局部变量:每调用一次方法,局部变量就会加载一次,最多可以加载无数次

* 实例变量:每创建一次对象,实例变量就会加载一次,最多可以加载无数次

​  

局部变量和实例变量在代码中的作用域不同,所以可以在同一个类中声明同名的实例变量和局部变量

this关键字的第一种用法:

* 位置:

* 实例方法中或构造器中

* 格式:

* this.实例变量名;

* this.实例方法名(实参);

* 作用: 用来区别同一个类中同名的实例变量和局部变量

* 含义: 哪个对象调用了this所在的实例方法或构造器,this关键字就代表哪个对象

封装思想

* 含义:给程序中不同的内容添加不同的访问权限级别,从而达到保护的效果

* 作用:

* 提供程序中内容的安全性

* 核心:

* 封装思想的核心中是四种权限访问级别

* 四种权限访问级别:

* 权限访问级别从大到小的关系如下:

* public > protected > 缺省(sheng三声) > private

* 解释:

* public:公共的

* protected:受保护的

* 缺省:什么都不写

* private:私有的

* private关键字:

* 含义:

* private关键字是封装思想的体现形式之一

* 修饰:

* 用来修饰成员变量,成员常量,构造器,成员方法,成员内部类

* 

* 私有实例变量:

* 含义:

* 被private修饰的实例变量

* 格式:

* private 数据类型 变量名;

* 作用:

* 被private修饰的内容只能在本类中访问,从外界无法进行访问

* 应用:

* 1.将类中所有的实例变量的进行私有化

* 2.针对每个被私有化的实例变量都提供一对的公共访问方式:set()和get()

#### 构造器

构造器(构造方法)

* 作用:

* 1.构造器中隐式的内容给对象进行成员初始化

* 2.构造器中显式的内容给对象进行变量的赋值

* 格式:

* 修饰符 类名 () {

* //隐式内容

* //显式内容

* }

构造器的注意事项:

* 1.构造器的名字必须和所在类名相同

* 2.构造器没有返回类型,而且连void都不能有

* 3.当一个类没有任何的构造器时,JVM自动给其分配一个public无参构造器,用来给对象的成员进行初始化,

* 一旦这个类有任何构造器时,JVM不再给其提供

* 4.构造器支持重载

* 5.构造器中包含两个部分,显式部分和隐式部分,隐式部分代码优先于显式部分的代码

//使用无参构造器创建对象

//使用满参构造器创建对象

Student s2 = new Student("张大芳", 18);

#### static

static关键字:

* 含义:静态的,共享的;

* 修饰:成员常量,成员变量,成员方法,成员内部类,代码块

* 作用:被static修饰的内容,不再属于对象自身,而是归属于类,会被通过这个类创建的所有对象所共享

静态变量:

* 含义:在类中方法外,且含有static关键字修饰的变量

* 格式:

* 修饰符 static 数据类型 变量名;

* 作用:

* 被static修饰的变量不再属于对象,而是归属于类,会被通过这个类创建的所有对象所共享

* 调用:

* 类名.静态变量名;

​  

#### 三种变量的区别:

* 局部变量:声明在代码块中或者代码块声明上的变量

* 实例变量:声明在类中方法外,且没有static关键字修饰的变量

* 静态变量:声明在类中方法外,且含有static关键字修饰的变量

* 

* 区别:

* 代码中声明的位置不同:

* 局部变量:代码块中或者代码块声明上

* 实例变量:类中方法外

* 静态变量:类中方法外

* 内存中存储的位置不同:

* 局部变量:栈内存

* 实例变量:堆内存

* 静态变量:堆内存

* 是否含有默认值不同:

* 局部变量:没有

* 实例变量:含有

* 静态变量:含有

* 代码中变量的作用域不同:

* 局部变量:所属方法中

* 实例变量:所属类中(静态方法,静态常量,静态代码块,静态成员内部类中无效)

* 静态变量:所属类中

* 内存中变量的生命周期不同:

* 局部变量:随着方法的调用而加载,随着方法的出栈而消失

* 实例变量:随着对象的创建而加载,随着对象的回收而消失

* 静态变量:随着类的加载而加载,随着类的回收而消失

* 加载方式和次数不同:

* 局部变量:每调用一次方法,局部变量就会加载一次,最多可以加载无数次

* 实例变量:每创建一次对象,实例变量就会加载一次,最多可以加载无数次

* 静态变量:考虑到类只加载唯一的一次,静态变量也只加载唯一的一次

* 

静态方法:

* 含义:声明在类中,且含有static修饰的方法

* 格式:

* 修饰符 static 返回类型 方法名 () {}

* 作用:

* (1)被static修饰的方法,不再归属于对象,而是归属于类,会被通过这个类创建的所有对象所共享

* (2)当有些类的存在不会为了创建对象的,而是为了封装功能方法,考虑如果这些方法是实例方法必须创建对象, 这个对象始终会在堆内存驻留,浪费内存空间,可以将这些方法直接声明静态方法,从而可以通过类名进行调用,从而提高内存使用率,与此同时,必须将该类的构造器进行私有化

* 调用:

* 类名.方法名(实参);

静态方法的注意事项:

* 1.静态方法随着类的加载而加载,而且只加载唯一的一次

* 2.在静态方法中不可以使用实例成员

* 3.在静态方法中不可以使用this关键字

​

单例设计模式:

* 含义:创建唯一实例的专用解决方案

* 解决方案:

* 立即加载(饿汉式)

* 延迟加载(懒汉式)

* 

* 立即加载(饿汉式)步骤:

* 1.将创建唯一对象所对应类的构造器进行私有化

* 2.在唯一对象所对应的类中创建唯一的对象

* 3.为了本类之外获取该类,进行static修饰

* 4.为了保证数据的安全性,需要进行private修饰

* 5.对外提供公共get()获取功能

延迟加载(懒汉式)步骤:

* 1.将创建唯一对象所对应类的构造器进行私有化

* 2.在唯一对象所对应的类中声明唯一对象的变量

* 3.为了本类之外获取该对象,进行static修饰

* 4.为了保证数据的安全性,需要进行private修饰

* 5.对外提供公共get()获取功能,并在第一次获取该对象的同时创建唯一对象

#### 继承

继承关系中的名词解释:

* 子类:被抽取相同属性和行为的多个类

* 父类:抽取多个子类中相同属性和行为构成的类

* 继承关系:子类和父类之间的关系

* 

* 继承关系的特点:

* 子类继承父类的属性和行为,使子类对象拥有父类相同的属性和行为

* 

* 继承关系的好处:

* 1.提高代码的复用性,从而提高开发效率

* 2.提高代码的扩展性

* 3.学习继承关系是学习实现关系的前提条件之一(继承和实现高度相似)

* 4.学习继承关系是学习多态体系的前提条件之一

* 

* 继承的格式:

* public class 父类类名 {}

* 

* public class 子类类型 extends 父类类名{}

​  

继承关系的特点

* 1.Java中的继承关系只支持单继承,不支持多继承

* 2.虽然不支持多继承,但是支持多层继承

* 3.在程序中父类和子类只是一对相对的概念

* 例如:C类继承B类,B类继承A类

* C类是B类的直接子类,C类是A类的间接子类,B类是A类的直接子类

* A类是B类的直接父类,A类是C类的间接父类,B类是C类的直接父类

* 4.在程序中一个子类最多只能拥有一个直接父类;一个父类可以拥有多个子类

* 5.Java中所有的类都拥有一个共同的父类,这个父类叫做Object类

​  

继承的特点:

* 子类继承父类的属性和行为,使之子类对象拥有和父类相同的属性和行为

* 

* 继承关系中成员的特点:

* 私有成员

* 静态成员

* 实例变量

* 实例方法

* 构造器

* 

* 继承关系中私有成员的特点:

* 官方解释:

* 1.子类可以继承父类中所有的成员

* 2.子类可以继承所有的public和protected成员,如果在同一个包下可以继承私有成员

* 3.子类不可以继承父类中的私有成员,但是可以针对私有成员属性的public和protected的方法可以继承

* 自己总结:

* 子类可以继承父类中的私有成员,但受限于private关键字的特点,可以通过public或protected的set()和get()进行存储和获取

#### 方法的重写(Override):

* 在继承关系(或者实现关系)的程序中,出现了方法名相同,形参列表相同,权限访问级别和返回类型遵循相关规则的现象

* 

* 方法重写的前提条件:

* 1.必须在继承关系(或者实现关系)

* 2.子类重写后方法名必须和父类被重写的方法名相同

* 3.子类重写后方法的形参列表必须和父类被重写方法的形参列表相同

* 4.子类重写后方法的权限访问级别必须大于等于父类被重写方法的权限方法级别,并遵循方法重写注意事项中关于权限访问级别的规则

* 5.在内存中,子类重写后方法的返回类型必须等于父类被重写方法的返回类型

* 

* 方法重写的注意事项:

* 1.在程序中有语法和方法的重写比较相似,程序并没有编译报错提示,可以通过方法重写的注解验证是否符合方法重写规则,如果不符合直接编译报错提示

* 注解:其实就是一个特殊的接口,用来检测Java中的特定语法规则

* 格式:

* @Override

* 修饰符 返回类型 方法名 () {

* 子类重写后方法体

* }

* 2.父类中的静态方法不能被重写

* 3.父类中的私有方法不能被重写

* 4.如果子父类不在同一个包下,父类的缺省方法不可以被重写

* 5.在代码中,子类重写父类的方法,

* 当父类被重写方法的返回类型为void时,子类重写后方法的返回类型必须和父类被重写方法的返回类型相同

* 当父类被重写方法的返回类型为基本类型时,子类重写后方法的返回类型必须和父类被重写方法的返回类型相同

* 当父类被重写方法的返回类型为引用类型时,子类重写后方法的返回类型必须和父类被重写方法的返回类型相同或者可以是父类被重写方法返回类型的子类类型(其实就是变相的多态)

* 

继承关系中构造器的特点:

* 子类不可以继承父类的构造器,但可以进行调用,在初始化子类成员之前,先初始化父类成员

​  

继承关系中构造器的注意事项:

* 在子父类继承关系中,当子类的构造器中没有任何this()和super(),JVM自动提供一个无参的super(),用来初始化子类对象成员之前,初始化父类引用成员,一旦当子类的构造器拥有this()或super(),JVM不在自动提供

​  

this关键字的第二种用法:

* 场景:

* 子类的构造器中

* 格式:

* this(实参);

* 作用:

* 调用本类中其它的构造器完成对象的成员初始化

* 含义:

当构造器本身无法进行对象成员初始化时,需要使用this(实参)调用本类中其它的构造器完成对象成员的初始化

* 

* super关键字的第二种用法:

* 场景:

* 子类的构造器

* 格式:

* super(实参);

* 作用:

* 调用父类中对应的构造器,完成父类引用成员的初始化

* 含义:

* 在初始化子类对象成员之前,先通过隐式或显式的super(实参)调用父类的构造器完成父类引用的成员初始化

​  

this和super关键字的注意事项:

* 1.在静态成员(方法,代码块,成员内部类)中无法使用this和super关键字

* 2.this(实参)和super(实参)在构造器中必须编译在第一行

* 3.this(实参)和super(实参)不能同时使用

* 4.程序中的构造器执行分三个阶段:

* (1)显式或隐式的super(实参);

* (2)隐式部分代码(实例初始化过程)

* (3)显式部分代码

Object类:

* 类的位置

* java.lang

* 类的特点

* 1.Object类是类层次的顶级父类

* 2.所有的对象(包括数组)调用Object类的中的方法

* 3.所有的接口隐式包含Object类中所有方法的抽象形式(暂不涉及)

* 类的构造器

* Object() 用来创建子类对象时,在子类构造器中调用super()

* 类的方法

* public boolean equals(Object obj)

* 指示其他某个对象是否与此对象“相等”。

* public String toString()

* 返回该对象的字符串表示。

* 

* == 和 equals()的区别:

* ==既可以比较基本类型,也可以比较引用类型

* 当比较基本类型时,比较的是基本类型的数据值

* 当比较引用类型时,比较的是引用类型的地址值

* equals()只能比较引用类型

* 当比较引用类型时,比较的是引用类型的地址值

* 如果当这个类型重写了Object中的equals(),需要按照重写后的规则进行比较

* 

* Object类中toString()的注意事项:

* 如果在输出语句中使用对象名的字符串形式,其实就是在通过对象名调用自己的toString(),在输出语句中打印char[]除外

封装:

* 在程序中给各个内容添加不同的权限访问级别,封装思想的核心就是四种权限访问级别

* 

* 四种权限访问级别从大到小的关系:

* public > protected > 缺省 > private

* 

* private关键字的权限修饰范围

* 被private修饰的内容在本类中有效,在本类之外无法进行访问

* 缺省(什么都不写)的权限范围

* 缺省的内容在同一个包中有效,在本包之外无法进行访问,兼容private关键字的权限修饰范围

* protected关键字的权限修饰范围

* 被protected修饰的内容在同一个项目中不同包且有继承关系有效,一旦同一个项目中无继承关系则无效,兼容缺省权限范围

* public关键字的权限修饰范围

* 被public修饰的内容在同一个项目中有效,一旦超出项目的范围则无效,兼容protected关键字的权限修饰范围

* 

* 注意事项:

* 1.如果开发工具是idea,在同一个项目中且跨模块使用,需要修改项目的配置文件(通过Alt+Enter解决)

* 2.如果某些数据跨项目进行使用,需要使用"序列化"和"反序列化"进行操作(暂不涉及,IO部分讲解)

* 

权限访问级别补充:

* 如果修饰类文件(class,interface,enum):

* 权限访问级别:public和缺省,推荐public

* 如果修饰类(class)中成员常量

* 权限访问级别:四种都可以,推荐private

* 如果修饰类(class)中成员变量

* 权限访问级别:四种都可以,推荐private

* 如果修饰类(class)中成员方法

* 权限访问级别:四种都可以,推荐public和private

* 如果修饰类(class)中成员内部类

* 权限访问级别:四种都可以,推荐private

* 如果修饰类(class)中构造器

* 权限访问级别:四种都可以,推荐public和private

* 如果修饰类(class)中构造器代码块

* 权限访问级别:只能缺省

* 如果修饰类(class)中静态代码块

* 权限访问级别:只能缺省

* 如果修饰接口(interface)中的静态常量

* 权限访问级别:只能public,无论显式和隐式都是public

* 如果修饰接口(interface)中的抽象方法

* 权限访问级别:只能public,无论显式和隐式都是public

* 如果修饰接口(interface)中的默认方法

* 权限访问级别:只能public,无论显式和隐式都是public

* 如果修饰接口(interface)中的静态方法

* 权限访问级别:只能public,无论显式和隐式都是public

* 如果修饰接口(interface)中的私有方法

* 权限访问级别:只能private

* 如果修饰接口(interface)中的内部接口

* 权限访问级别:只能public,无论显式和隐式都是public

* 如果修饰枚举类(enum)中的枚举对象:

* 权限访问级别:只能隐式public,如果显式编译报错

* 如果修饰枚举类(enum)中的成员变量:

* 权限访问级别:四种都可以,推荐private

* 如果修饰枚举类(enum)中的成员方法:

* 权限访问级别:四种都可以,推荐public和private

* 如果修饰枚举类(enum)中的构造器:

* 权限访问级别:只能private,无论显式和隐式都private

* 如果修饰局部中的常量

* 权限访问级别:只能缺省

* 如果修饰局部中的方法

* 权限访问级别:只能缺省

* 如果修饰局部中的内部类

* 权限访问级别:只能缺省

* 

* protected关键字的修饰场景:

* 1.有继承关系的源码中

* 2.封装带有继承关系的工具类时

* 3.编写框架的源码

#### 抽象的由来:

* 1.多个子类抽取出来的父类,理论上不应该被创建对象,但实际上可以创建

* 2.通过父类重写后的方法被子类对象所调用,父类被重写方法的方法体显得就不是那么重要了,希望这个方法体可以不写提高开发效率,但是如果不写编译报错

* 3.当子类重写父类的方法时,如果某个子类忘记重写,希望忘记重写时,idea最好编译报错进行提示,但是实际上没有任何提醒

* 

* 抽象的出现就是为了解决上述继承关系中的三大问题

* 

* 抽象分类:

* 抽象类

* 抽象方法

* 

* 抽象类:

* 含义:

* 被abstract修饰的class,也叫做"加强版父类"

* 格式:

* public abstract class 父类类名 {}

* 特点:

* 1.在程序中抽象类无法进行实例化对象

* 2.在抽象类中可以含有构造器,构造器的作用不是创建父类对象,而是创建子类对象时初始化父类成员使用的

* 

* 抽象方法:

* 含义:

* 被abstract修饰,且没有方法体的方法

* 格式:

* 修饰符 abstract 返回类型 方法名 ();

* 特点:

* 1.抽象类中可以没有抽象方法,但含有抽象方法的类一定是抽象类

* 2.抽象类的子类必须重写抽象类中所有的抽象方法,除非该类也是抽象类

* /

#### final关键字

* 含义:

* 最终的,不可改变的

* 修饰:

* 类,方法,变量

* 作用:

* 被final修饰的类,不能被继承

* 被final修饰的方法,不能被重写

* 被final修饰的变量,不能被二次赋值,其实就是一个常量

* 

* 

* 被final修饰的类:

* 含义:

* 不能被继承

* 格式:

* public final class 类名 {}

* 注意事项:

* final关键字和abstract关键字不可以同时修饰一个类

​  

被final修饰的方法

* 含义:

* 不能被重写

* 格式:

* 修饰符 final 返回类型 方法名 () {}

* 注意事项:

* abstract关键字和final关键字不可以修饰同一个方法

​  

​  

被final修饰的变量:

* 含义:

* 不能被二次赋值,其实就是一个自定义常量

* 格式:

* 直接声明初始化:

* 修饰符 final 数据类型 常量名 = 常量值;

* 先声明后初始化

* 修饰符 final 数据类型 常量名;

* 常量名 = 常量值;

* 常量名的命名规范:

* 一个单词:单词字母全部大写

* 多个单词:所有单词字母全部大写,且每个单词间使用\_进行连接

* 分类:

* 局部常量

* 实例常量

* 静态常量

​  

实例常量:

* 含义:

* 被final关键字修饰的实例变量

* 注意事项:

* 1.程序中的实例常量在堆内存区域不会给其分配默认值,必须由手动给定

* 2.如果实例常量通过先声明后初始化,初始化的时候需要在所有的构造器中给其赋值

* 当所有构造器中初始化值相同,可以直接使用构造器代码块进行简化;

* 当所有构造器中初始化值不同,只能在每个构造器中给其进行赋值操作

* 

静态常量:

* 含义:

* 被final关键字修饰的静态变量

* 注意事项:

* 1.程序中的静态常量在堆内存区域不会给其分配默认值,必须由手动给定

* 2.如果静态常量通过先声明后初始化,初始化的时候需要在静态代码块中被赋值一次

#### 接口:

* 规定一组数据和行为的标准

* 

* 接口的好处:

* 1.提高代码的复用性,从而提高开发效率

* 2.提高代码的扩展性

* 3.学习多态的前提条件之一

* 4.学习匿名内部类的条件之一

* 

* 接口的格式:

* public interface 接口名 {

* 自定义常量(静态常量)

* 抽象方法

* 默认方法(JDK8.0)

* 静态方法(JDK8.0)

* 私有方法(JDK9.0)

* 内部接口(暂不涉及)

* }

* 

* 接口的实现格式:

* public class 实现类类名 [extends 父类类名] implements 父接口名1,父接口名2,......,父接口名n {

* 

* }

* 

* 注意:实现关系和继承关系高度类似,实现类可以继承接口中的内容

* 

* 接口的特点:

* 1.程序中的关系:

* 类与类之间的关系:单继承关系

* 类与接口之间的关系:多实现关系

* 接口与接口之间的关系:多继承关系

* 2.接口中没有构造器,所以无法进行实例化对象

* 3.接口使用的步骤:

* (1)找到需要使用的接口

* (2)创建接口的实现类

* (3)在实现类中重写接口中的抽象方法

* (4)在测试类中创建接口的实现类对象

* (5)通过实现类对象完成需求

​  

接口中的静态常量:

* 格式:

* [public] [static] [final] 数据类型 常量名 = 常量值;

* 注意事项:

* 1.格式中的[]代表关键字可以省略不写,如果省略不写,由JVM自动填充补全

* 2.接口中的静态常量不可以先声明后初始化

* 调用格式:

* 接口名.静态常量名;

​  

接口中的抽象方法:

* 格式:

* [public] [abstract] 返回类型 方法名();

* 注意事项:

* 格式中的[]代表关键字可以省略不写,如果省略不写,由JVM自动填充补全

​  

接口中的默认方法

* 含义:

* 所谓默认方法,其实就是原来父类中抽取多个子类相同且不需要重写的实例方法,考虑到接口不能创建对象,需要将该方法改写为默认形式

* 格式:

* [public] default 返回类型 方法名 () {}

* 注意事项:

* 格式中的[]代表关键字可以省略不写,如果省略不写,由JVM自动填充补全

* 应用场景:

* 1.源码中

* 2.笔试题

默认方法的注意事项:

* 1.当子类继承父类并实现父接口,父类中的实现方法和父接口中的默认方法发生同名的情况,

* 通过子类对象调用了该同名方法,执行的是父类的实例方法

* 2.当子类不继承父类,实现多个父接口,多个父接口中出现了同名的默认方法,子类必须以实例

* 方法的形式重写多个父接口中的默认方法

接口中的静态方法(JDK8.0)

* 格式:

* [public] static 返回类型 方法名 () {}

* 注意事项:

* 格式中的[]代表关键字可以省略不写,如果省略不写,由JVM自动填充补全

* 调用格式:

* 接口名.静态方法名(实参);

* 注意事项:

* 在继承关系中,静态成员可以被子类所继承

* 在实现关系中,静态方法不可以被实现类所继承

​  

接口中的私有方法(JDK9.0)

* 格式:

* 针对默认方法的抽取私有方法的格式

* private 返回类型 方法名 () {}

* 针对静态方法的抽取私有方法的格式

* private static 返回类型 方法名 () {}

#### 多态:

* 含义:事物在编译运行过程中的多种形态

* 当编译时状态和运行时状态一致的情况,称之为"单态"

* 当编译时状态和运行时状态不一致的情况,称之为"多态"

* 

* 程序中的多态:

* 单态:Cat cat = new Cat();

* 多态:Animal cat = new Cat();

​  

多态的前提条件:

* 1.必须要有"继承关系"或者"实现关系"

* 2.必须要有方法的重写(没有方法重写在格式上也可以构成多态,只不过这样多态没有任何意义)

* 3.如果是继承关系,父类的引用指向子类对象(父类new子类)

* 如果是实现关系,父接口的引用指向实现类对象(父接口new实现类)

* 多态的特殊形式:构造器中的super();(暂不涉及)

多态情况下构造器的特点:

* 和以前子类new子类时一样,构造器和多态无关

多态情况下实例变量的特点

* 和以前的方式使用特点一模一样,使用多态的时候无需关注实例变量

​  

多态情况下实例方法的特点:

* 使用多态对象调用方法,先调用父类(父接口)的方法,看是否存在,如果存在,不会执行父类(父接口)的方法,

执行子类(实现类)重写后的方法;如果不存在,编译报错

多态的好处:

* 1.学习多态是学习"匿名内部类"的前提条件之一

* 2.在程序中可能通过重载声明接收多个参数的方法,效率过低,直接声明最多对象的父类类型或者父接口类型即可

​  

多态的弊端:

* 多态的对象无法调用子类(实现类)特有的方法

* 

* 引用类型的类型转换

* 向上转型(自动转换)

* 将子类类型的对象转换为父类类型的对象(其实就是多态)

* 向下转型(强制转换)

* 将父类类型的对象转换为子类类型的对象

* 格式:

* 子类类型 对象名 = (子类类型)父类类型的对象;

* 

* 引用类型的向下转型的注意事项:

* 进行转型的时候,可能发生ClassCastException(类型转换异常),尽量避免使用向下转型

* /

​  

instanceof关键字

* 含义:

* 包含

* 格式:

* 对象名 instanceof 类名

* 作用:

判断指定的对象在存在中是否为指定的类型或者指定类型的子类类型,如果是返回true,如果不是返回false

#### 枚举(JDK5.0)

* 含义:针对创建固定数量对象的简化方式

​  

枚举类的格式

* public enum 枚举类类名 {

* 对象名1(实参),对象名2(实参),......,对象名n(实参);

* }

​  

枚举类的注意事项:

* 1.枚举类中对象隐式被public static final进行修饰

* 2.如果在枚举类中针对对象名进行显示使用,导致编译报错

* 3.枚举类中的对象声明位置必须在第一行,否则编译报错

* 4.在枚举类中声明构造器,无论显式还是隐式都是private

* 5.如果对象的声明创建使用无参构造器进行,可以在编写的过程中将对象名后面的()可以省略不写

* 6.当枚举类没有任何的构造器时,JVM会提供一个private的无参构造器,用来初始化枚举类的成员,如果一旦有任何的构造器,JVM不再进行提供

* 7.枚举类型不能通过new实例化对象

* 8.枚举类型不能拥有子类

实例成员内部类(实例内部类)

* 含义:

* 声明在类中方法外,且没有static修饰的内部类,内部类归属于"对象"

* 学习目的:

* 在程序中有些类不想被本类之外内容所访问,需要进行私有化,但是普通的类文件只能使用public和缺省进行修饰,无法进行私有化,需要将这个类移动到某个类中,然后再进行私有化

* 权限访问级别:

* 四种都可以,推荐private

* 格式:

* public class 外部类类名 {

* private class 内部类类名 {

* 

* }

* }

* 创建对象格式:

* 当实例内部类权限访问级别不是private时,

* 格式1:先创建外部类对象,再创建内部类对象

* 外部类类名 外部类对象名 = new 外部类类名();

* 外部类类名.内部类类名 内部类对象名 = 外部类对象名.new 内部类类名();

* 格式2:直接创建内部类对象

* 外部类类名.内部类类名 内部类对象名 = new 外部类类名().new 内部类类名();

* 当实例内部类权限访问级别是private时,

* 格式:在外部类的实例方法中创建内部类对象

* 内部类类名 内部类对象名 = new 内部类类名();

* 注意事项:

* 1.在内部类中可以访问外部类所有非同名成员

* 2.如果在内部类中访问同名的外部类成员,需要使用Outer.this进行访问

* 3.在实例成员内部类中不能声明静态成员,如果想在成员内部类中声明静态成员,选择静态成员内部类

* 4.通过内部类对象名可以在外部类中可以访问其私有成员

* 

静态成员内部类(静态内部类)

* 含义:

* 声明在类中方法外,且含有static修饰的内部类,内部类归属于"类"

* 学习目的:

* 在程序中有些类不想被本类之外内容所访问,需要进行私有化,但是普通的类文件只能使用public和缺省进行修饰,无法进行私有化,需要将这个类移动到某个类中,然后再进行私有化

* 权限访问级别:

* 四种都可以,推荐private

* 格式:

* public class 外部类类名 {

* private static class 内部类类名 {

* 

* }

* }

* 注意事项:

* 1.在内部类中可以访问外部类所有成员

* 2.在静态成员内部类中可以声明实例成员,如果在外部类中想使用这些实例成员需要创建内部类对象才能使用

* 3.通过内部类名可以在外部类中可以访问其私有成员

* /

标准局部内部类:

* 含义:

* 主要是声明在方法内部的局部内部类

* 学习目的:

* 1.学习"标准局部内部类"是学习匿名内部类的基础

* 2.笔试题

* 权限访问级别:

* 只能是缺省

* 格式:

* public class 外部类类名 {

* 修饰符 返回类型 方法名 () {

* class 内部类类名 {

* 

* }

* }

* }

* 注意事项:

* 1.只能在局部内部类所属方法中进行内部类对象的创建

* 2.在内部类中可以访问外部类所有非同名的成员

* 3.当内部类所属方法中的局部变量和内部类的实例变量或局部变量发生同名的时候,在内部类中无法使用该外部类的局部变量

* 4.如果在内部类中使用所属方法的局部变量,在内部类中默认将其进行final修饰,因为变量的初始化是根据数据类型所决定,一旦该局部变量出栈,在字节码文件中进行赋值没有数据类型,导致编译报错,但是被final修饰的内容存储方法区中的"常量区", 可以将其理解为一个字面值常量

匿名局部内部类(匿名内部类)

* 学习目的:

* 2.学习匿名内部类是学习Lambda表达式的前提条件

* 格式:

* 接口名 实现类对象名 = new 接口名 (){

* 接口实现类的类体

* };
