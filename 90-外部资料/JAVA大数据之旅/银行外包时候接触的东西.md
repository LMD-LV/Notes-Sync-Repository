# docker

虚拟化时代：镜像是以虚拟机为整个为单位的，比较笨重gb级别，创建辅助、同一虚拟机内的应用隔离性差，相互抢占资源，一个应用内存泄露则其他的应用也受影响，启动慢，移植分享需要以虚拟机为单位不方便

容器化时代：镜像以应用为单位，创建简单，各自应用占用各自资源，启动起来快，移植也只用移植单个应用更方便

## 一、作用

1.应用构建：传统的不同语言写的应用需要以不同的方式（java - jar、c++编译等） ，docker可以将这些应用通过docker build ... -》镜像

2.应用分享：所有的软件的镜像放入到一个指定的地方 如：docker hub，这就类似于手机上 应用宝 的功能

3.应用运行：拿到统一标准的镜像，然后docker run.... 运行应用

4.资源隔离：cpu、内存资源的隔离、访问设备隔离与限制、网络隔离与限制、用户用户组隔离限制

## 二、架构

docker\_host：主机，每个节点都要安装

docker daemon：docker后台线程

client：docker命令行

registry：docker镜像仓库 如 docker hub

交互逻辑：装好docker，通过client（docker命令行）去registry寻找镜像image，下载并运行，查看容器状态日志等拍错

# 云服务器的一点点

## 一、购买

​  

## 二、安全组

1.阿里云安全组即为该服务器的防火墙

2.防火墙的相关端口设置

3.配置入方向：将对应的端口暴露给对应的ip 如 0.0.0.0（全部人开放，但是易被攻击）

4.暴露后，利用服务器ip+端口号即可连接，如yarn的8088等

## 三、公网ip与私有ip

1.公网ip是外部连接使用的，如阿里云服务器的公网ip不间断会刷新变化

2.私网ip：同一个集群内，使用私有ip连接，更快，更省钱

3.vpc：私有网络（专有网络），如192.168.0.0/16 即32位的二进制ip前16位不可变化，即该网络范围为192.168.0.0-192.168.255.255 共有65534个，其中192.168.255.255是广播ip。如192.168.0.0/24 则是前24个不可变化，范围有255个。

4.vpc作用：创建多个vpc，如开发、测试、生产三个vpc，每个vpc内的ip互通、但是不同vpc不互通。

#### 6.安装完成后

-   rke2-server 服务将被安装。rke2-server 服务将被配置为在节点重启后或进程崩溃或被杀时自动重启。
-   其他的实用程序将被安装在/var/lib/rancher/rke2/bin/。它们包括 kubectl, crictl, 和 ctr. 注意，这些东西默认不在你的路径上。
-   还有两个清理脚本会安装到 /usr/local/bin/rke2 的路径上。它们是 rke2-killall.sh和rke2-uninstall.sh。
-   一个 [kubeconfig](https://kubernetes.io/docs/concepts/configuration/organize-cluster-access-kubeconfig/) 文件将被写入/etc/rancher/rke2/rke2.yaml。
-   一个可用于注册其他 server 或 agent 节点的令牌将在 /var/lib/rancher/rke2/server/node-token 文件中创建。
