# 每周分拣工作流

> [!note] 用途
> 2026-09-08 建立(第二期治理收尾固化)。每周挑一个固定时间(建议周五或周日)按下面三步走一遍,维持库的秩序。全程 10~15 分钟。

## 第一步:跑健康巡检(1 分钟)

在仓库根目录运行:

```bash
PYTHONIOENCODING=utf-8 python scripts/库健康巡检.py --save
```

报告同时打印并写入 [[库健康巡检报告]]。五项检查的含义与处置:

| 检查项 | 出现告警时 |
| --- | --- |
| 断链 | 要么创建占位种子笔记,要么删链接——不留悬空引用 |
| frontmatter 缺失 | 用 `Templates/标准笔记` 规范补齐,不确定归属的先扔 00-收件箱 |
| 超大文件 >50KB | 登记进当期治理计划,参照 Flink/Hadoop 模式拆分 |
| 未登记碎片 | 有内容的标 `status: 种子`,空壳删除或并入同类 |
| 待重组残留 | 拆分或合并后更新状态 |

## 第二步:清空收件箱(5~10 分钟)

`00-收件箱` 以清空为目标,逐件分拣:

- 想法/待验证 → [[想法收件箱]] 或 [[零散待做清单]]
- 明确的学习内容 → 按主题归入 10 区对应文件夹(新笔记带规范 frontmatter)
- 工作内容 → 20 区对应项目文件夹
- 个人内容 → 30 区(只归类,不改写正文)

**长期驻留件不算欠账**:治理清单、开放问题清单、断链/巡检报告属于工具笔记,不参与"清空"考核。

## 第三步:顺手维护(几分钟)

- 新入库内容让链接落地:被提及但没建笔记的概念,创建种子占位,同时挂进所属 MOC
- 翻一眼 [[开放问题清单]],本周若学到相关内容,顺手解答一条并移入"已解决"
- git 提交一次(`git add -A && git commit -m "周分拣:日期"`),保持可回滚

## 原则(与 [[笔记库规范]] 一致)

1. 90-外部资料只读,不修改不打标签
2. 不随手改老笔记正文,结构问题走巡检报告
3. 30-个人区只归类不改写
4. 批量操作前确认工作区干净,按主题分批提交
